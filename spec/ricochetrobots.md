# ricochetrobots 플러그인 스펙

## 개요
- **id**: `ricochetrobots`
- **이름**: 리코셰 로봇
- **목적**: 보드게임 "Ricochet Robots"를 본뜬 1인 미니게임. 선택한 로봇을 벽/다른 로봇에 막힐 때까지 미끄러뜨려 목표 칸까지 보내는 퍼즐.
- **위치**: `src/plugins/ricochetrobots/`
- **멀티플레이 없음** — 사용자 명시 요구사항

## 파일 구성
| 파일 | 역할 |
|------|------|
| `manifest.json` | 메타데이터 (id/name/icon/defaultSize/minSize) |
| `index.jsx` | UI 컴포넌트 — 헤더(이동 횟수/목표/설정/새 게임), 설정 패널, 보드 렌더링, 클릭/키보드 조작 |
| `board.js` | 보드 생성(`generateBoard`)과 이동 계산(`moveRobot`, 대각선 디플렉터 포함) 순수 함수 |
| `style.css` | 보드/로봇/타겟/설정 패널 스타일 |

## 기능 명세

### 보드 생성 (`board.js`)
- `generateBoard({ size, diagonalWalls })` — 크기와 대각선 벽 여부를 옵션으로 받음
- 벽 개수 = `round(size² × 0.15)`, 랜덤 셀+방향으로 생성, 양쪽 셀에 대칭으로 설정(`{N,E,S,W}` 플래그)
- **중앙 2x2 정사각형 벽**: 보드 정중앙에 2x2 칸을 막힌 블록으로 배치(보드 둘레 전체에 벽), 로봇/타겟/디플렉터는 이 칸에 배치되지 않음 — 슬라이드의 기준점이 되어 너무 빈 보드의 난이도를 낮춤(공식 Ricochet Robots의 중앙 블록과 동일한 의도)
- 로봇 4개: 빨강/초록/파랑/노랑, 서로 겹치지 않는 랜덤 칸에 배치
- 타겟: 로봇과 겹치지 않는 랜덤 칸 + 랜덤 색(해당 색 로봇이 도착해야 클리어)
- `diagonalWalls`가 true면 대각선 디플렉터를 `round(size² × 0.04)`개, 로봇/타겟과 겹치지 않는 칸에 배치. 각 디플렉터는 `{ shape: "slash"|"back", color: <로봇 색 4종 중 하나> }` — 모양(`/` 또는 `\`)과 색을 함께 가짐 (공식 Ricochet Robots 룰 반영, 아래 참조)
- **풀이 가능성 검증**: 보드를 만들 때마다 깊이/노드 수 제한 BFS(`isSolvable`)로 "목표색 로봇이 목표 칸에 도달 가능한가"를 확인. 실패하면 최대 `MAX_GEN_ATTEMPTS`(40)번까지 재생성하고, 그래도 못 찾으면 마지막 시도를 그대로 사용(아주 드문 폴백, 보장은 아님). 탐색 폭발 방지를 위해 `MAX_SOLVE_DEPTH`(10수)와 `MAX_SOLVE_NODES`(방문 상태 1500개) 한도를 두고, 한도 도달 시 해당 시도는 "실패"로 간주해 재생성

### 이동 (`moveRobot`)
- 선택된 로봇을 지정 방향으로 한 칸씩 이동 시도하다가 벽, 보드 경계, 다른 로봇과 만나면 정지(슬라이드 이동, 멈춰서기 불가)
- 진입한 칸에 대각선 디플렉터가 있을 때:
  - **로봇 색 == 디플렉터 색**: 그대로 통과(방향 유지) — 모든 로봇이 무조건 튕기는 게 아니라, **자기 색 디플렉터는 무시하고 직진**하는 것이 공식 룰
  - **로봇 색 != 디플렉터 색**: 진행 방향을 90도 전환해 계속 슬라이드 (`slash`: 상↔우, 하↔좌 / `back`: 상↔좌, 하↔우)
  - 무한 루프 방지를 위해 `size² × 4` 스텝에서 강제 종료

### 조작
- 로봇 클릭 → 선택(다시 클릭하면 선택 해제, 흰색 테두리로 강조)
- 선택된 로봇은 방향키(↑↓←→)로만 이동 (화면 버튼 없음)
- 이동 후 위치가 바뀌지 않으면 이동 횟수 미증가

### 설정 (카드 헤더 공통 ⚙ 버튼)
- 플러그인 카드 헤더(✕ 옆)의 공통 ⚙ 버튼 클릭 시 모달 오버레이로 설정 팝업 표시 (`PluginCard`의 공용 메커니즘 — `index.jsx`가 `Settings` 컴포넌트를 export하면 자동 노출)
- 오버레이가 열려 있는 동안 보드와의 상호작용(로봇 선택/이동)은 차단되며, 팝업의 ✕ 또는 바깥 클릭으로 닫힘
- **판 크기**: 8 / 12 / 16 / 20 / 24 중 선택 (기본 12)
- **대각선 벽**: 체크박스로 디플렉터 생성 여부 토글 (기본 꺼짐)
- 설정 변경 시 인스턴스 storage(`settings` 키)에 저장 + `bus.emit("plugin:settings-changed", { instanceId })`로 메인 컴포넌트에 알림 → 새 보드로 즉시 재시작(이동 횟수/선택/클리어 초기화)

### 애니메이션
- 로봇은 `rr-robot-wrap`에 `left`/`top` 퍼센트 위치를 적용하고 `transition: left/top 0.12s ease`로 슬라이드 이동을 부드럽게 표시 (즉시 점프 대신 빠른 이동 애니메이션)
- `moveRobot`이 반환하는 `path`(디플렉터로 꺾이는 지점들 + 최종 정지 지점)를 따라 120ms 간격으로 순차 이동 — 디플렉터를 거쳐 여러 번 꺾이는 이동도 각 구간이 끊어져 보임 (목적지로 한 번에 직선 이동하지 않음)

### 시각 디자인
- 보드는 앱 전체와 동일한 다크 테마(`#15171c` 배경, `#343945` 테두리), 직교 벽은 밝은 파란색(`#8ab4f8`) 굵은 테두리, 대각선 디플렉터는 **자신의 색(빨강/초록/파랑/노랑)에 해당하는 로봇 색 사선 그라데이션 줄무늬**로 표시 (어떤 색 로봇이 통과하는지 시각적으로 구분)
- 보드는 `container-type: size` + `min(100cqw, 100cqh)`로 항상 정사각형 셀 유지 (로봇/타겟이 타원으로 찌그러지지 않음)
- 로봇/타겟은 보드 내 퍼센트 좌표로 절대 배치(`rr-robot-wrap`/`rr-target-wrap`), 로봇은 원형(입체감 있는 그라데이션 음영), 타겟은 해당 색으로 채워진 별(`clip-path` 5각 별)

### 진행/목표
- 헤더에 이동 횟수, 목표 색상(점 + 색상명) 표시
- "새 게임" 버튼: 현재 설정으로 보드/로봇/타겟 전부 재생성, 이동 횟수 0으로 초기화
- 클리어(목표 색 로봇이 목표 칸 도달): 보드에 "클리어! 🎉" 오버레이 표시 후 1.4초 뒤 자동으로 새 게임

### 2026-06-15 (이어서, 대각선 디플렉터 규칙을 공식 룰로 수정)
- 사용자 피드백: "대각선 벽 스펙은 좀 다르다, 모든 게 튕겨나가는 스펙이 아니다" → 웹 검색으로 공식 Ricochet Robots 룰 확인. **대각선 벽은 색을 가지며, 같은 색 로봇은 그대로 통과하고 다른 색 로봇만 90도 꺾여 진행**하는 것이 정확한 규칙 (이전엔 색 구분 없이 모든 로봇이 무조건 90도 꺾였음)
- `board.js`: `diagonals[y][x]`를 단순 문자열(`"slash"|"back"`)에서 `{ shape, color }` 객체로 변경, `color`는 로봇 4색 중 랜덤 배정. `moveRobot`은 진입한 디플렉터의 `color`가 이동 중인 로봇의 색과 같으면 방향을 유지(통과), 다르면 `DEFLECT[shape]`로 90도 전환
- `index.jsx`: 대각선 그라데이션 색을 디플렉터의 `color`에 맞는 로봇 색(`#e74c3c`/`#2ecc71`/`#3498db`/`#f1c40f`)으로 표시 — 어떤 로봇이 통과하는지 보드에서 바로 식별 가능
- 검증: `npm run build` ✅, 브라우저 콘솔에서 `board.js`의 `moveRobot`을 직접 호출해 단위 테스트 — 같은 색 로봇은 디플렉터를 관통해 반대편 벽까지 직진(`(2,0)→(7,0)`), 다른 색 로봇은 디플렉터에서 90도 꺾여 진행(`(0,1)→right→(4,1) 디플렉터→down→(4,7)`) 확인. 프리뷰에서 디플렉터가 색상별 그라데이션으로 렌더링되는 것도 확인

### 2026-06-15 (이어서, 보드 풀이 가능성 검증 추가)
- 사용자 질문: "이거 풀이가 100% 있다는게 검증이 됐어?" → 기존엔 보드를 완전 랜덤 생성만 하고 풀이 가능성 검증이 없었음. 이어서 "(BFS가) 엄청 느릴지도 모르겠다"는 우려에 따라 성능을 먼저 측정하며 구현
- `board.js`에 `isSolvable(board)` 추가: 4개 로봇 위치 조합을 상태로 하는 BFS로, 목표색 로봇이 목표 칸에 도달하는 전이가 나오면 즉시 `true` 반환. `generateBoard`는 내부 `buildBoard`로 보드를 만들고 `isSolvable`을 통과할 때까지(최대 40회) 재생성
- **첫 구현(깊이 8수, 무제한 노드)은 너무 느렸음** — "해 없음"을 증명하려면 깊이 한도까지 전체 탐색을 끝내야 하는데, 4로봇 위치 조합 상태공간이 매 단계 최대 16개씩 분기해 깊이 8에서 폭발(size=20/대각선 조합에서 generateBoard 1회가 최대 3.6초, 일부는 30초 타임아웃까지 발생)
- **해결**: 깊이 한도를 10수로 늘리는 대신 **방문 상태 수 한도(`MAX_SOLVE_NODES=1500`)**를 추가 — 한도에 닿으면 그 시도는 "실패"로 간주하고 즉시 재생성으로 넘어감(해 없음을 증명하느라 시간을 쓰지 않음). 재생성 시도 한도도 60→40으로 축소
- 검증: 브라우저 콘솔에서 `generateBoard({size, diagonalWalls})`를 size 8/12/16/20/24 × diagonalWalls true/false 각 8~20회 반복 측정 — 평균 4~146ms, 최악(24x24+대각선, 20회 표본) 259.7ms로 "새 게임" 클릭 시 체감 지연 없는 수준. `npm run build` ✅, 프리뷰에서 24x24+대각선 보드 정상 렌더 확인
